Credentials (Hashes & Cracking)

"I'm on the box — how do I steal passwords?"

📈 Valid Credential Attacks

According to IBM X-Force 2024, there has been a massive year-over-year increase in attacks using valid credentials. Attackers walk through the front door with stolen keys rather than breaking windows.

⚙️ The Cracking Workflow
  1. Obtain hashes: Dump /etc/shadow or SAM database.
  2. Identify hash type: Use hashid.
  3. Choose attack mode: Dictionary, Rule-Based, Mask, or Brute-Force.
  4. Run tool: Hashcat (GPU) or John the Ripper (CPU).
  5. Analyze: Find password reuse and weak policies.
⚡ Hash Cracking Speed Comparison

Demonstrating the difference between fast hashes (MD5, NTLM) and slow, salted hashes (bcrypt) using an NVIDIA RTX 4090. Note the logarithmic scale on the Y-axis.

Values in Hashes per Second. MD5/NTLM are in the billions; bcrypt is in the thousands.

Key Takeaway

Hash cracking is a comparison game. Weak passwords fall in milliseconds. Strong passwords (14+ chars, random) resist even GPU rigs. Defensive answer: bcrypt/Argon2 + salts + MFA.

Local Privilege Escalation (LPE)

"I'm a low-privilege user — how do I become root or SYSTEM?"

Initial access usually gives you www-data or a standard user. Enumeration is 90% of privilege escalation. Use tools like LinPEAS or WinPEAS to identify the vectors below.

🐧 Linux Vectors (Root)
  • ▪
    SUID Binaries: Executables running as file owner (check GTFOBins).
  • ▪
    Sudo Misconfigs: sudo -l reveals flaws like NOPASSWD.
  • ▪
    Cron Jobs: World-writable scripts executed on a schedule.
  • ▪
    Kernel Exploits: DirtyCow, DirtyPipe (Test in lab first!).
  • ▪
    PATH Hijacking: Malicious binaries placed earlier in writable PATHs.
🪟 Windows Vectors (SYSTEM)
  • ▪
    Unquoted Service Paths: Spaces in paths trick OS into running intermediary binaries.
  • ▪
    Token Impersonation: Potato Attacks (Juicy Potato, PrintSpoofer).
  • ▪
    AlwaysInstallElevated: GPO allowing MSI installs as SYSTEM.
  • ▪
    Stored Credentials: Registry, RDP sessions, cmdkey.
  • ▪
    DLL Hijacking: Apps loading DLLs without full paths.
Key Takeaway

Root/SYSTEM is the real prize. Prefer "living-off-the-land" over uploading exploit binaries. Always test kernel exploits in your lab first to avoid crashing production servers.

Why Persistence Matters

Multi-day engagements require reliable re-access. It also demonstrates real-world risk to the client—proving an attacker survives a reboot or password rotation.

Linux Methods
  • Cron Jobs
  • SSH Authorized Keys
  • Bash Profile Injection
  • Systemd Services
Windows Methods
  • Registry Run Keys
  • Scheduled Tasks
  • Windows Services
  • WMI Event Subs
⚠️
The Cleanup Imperative

A persistence mechanism left behind by a tester becomes a real vulnerability. Remove all accounts, executables, and persistence. Securely delete files (shred/sdelete) and restore original configurations.

OPSEC (Operations Security)

"How do I avoid getting caught during all of this?"

OPSEC wraps around every phase of system hacking. Every action creates evidence. You must manage your Network, Disk, and Behavioral footprints to remain undetected by the SOC.

🌐
Network Footprint

DNS queries, SMB traffic, scan patterns.

💾
Disk Footprint

Uploaded tools, Event IDs (4688, 4624), registry changes.

📊
Behavioral Footprint

Command bursts, privilege spikes, odd timing.

The OPSEC Lens Applied
  • 🛡️ Credentials: Crack hashes offline. Never use 3rd-party online crackers.
  • 🛡️ Privilege Escalation: Prefer LOLBins over custom exploits. Time attempts for low-monitoring periods.
  • 🛡️ Persistence: Name services to blend in. Use encrypted C2 channels. Clear logs carefully (clearing all creates ID 1102).
📜 Rules of Engagement (RoE)

Without a signed RoE defining systems, allowed techniques, and blackout windows, you are not a penetration tester — you are an unauthorized intruder.

🛡️ Defensive Takeaways (Blue Team)

Penetration testing is only valuable if it improves defense. This section summarizes the actionable recommendations derived from the System Hacking attack chain, designed to help network defenders and SOC analysts harden their environments.

🔐
Identity & Access

Use modern hashing (bcrypt, Argon2id). Enforce 14+ character passwords combined with MFA everywhere.

🔍
System Auditing

Regularly audit Linux SUID binaries, sudo rules, and Windows scheduled tasks. Patch older kernels to prevent exploits.

👁️
SIEM Monitoring

Alert on Event IDs 4688 (Process Creation), 4624 (Logon), 7045 (Service Installed), and 1102 (Audit Log Cleared).

🚨
Proactive Testing

Conduct regular penetration tests to identify persistence mechanisms and escalation paths that automated defenders miss.
