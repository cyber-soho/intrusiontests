To understand current vulnerabilities, you must understand the history of Wi-Fi protocols. This section details the IEEE 802.11 standard family and the evolution of encryption mechanisms. A protocol's version directly dictates its available attack surface, making reconnaissance critical.

Wi-Fi Encryption Evolution

WEP

1999
  • RC4 cipher, 24-bit IV
  • Crackable in ~3 minutes
  • Fundamentally Broken

WPA

2003
  • TKIP encryption
  • Still uses RC4 underneath
  • Deprecated. Vulnerable.
TARGET

WPA2

2004
  • AES-128 via CCMP
  • 4-way handshake
  • Vulnerable to PMKID

WPA3

2018
  • SAE (Dragonfly) handshake
  • Resists offline dictionary
  • Secure (if no transition mode)

The core of the WPA2 protocol is the 4-way handshake, used to establish session keys. The PMKID attack exploits a specific piece of data transmitted in the very first message of this handshake. Explore the formula below to understand exactly what mathematical components are captured and eventually cracked.

The WPA2 4-Way Handshake

Msg 1
AP → Client: ANonce + PMKID (in RSN IE)
Msg 2
Client → AP: SNonce + MIC
Msg 3
AP → Client: GTK (encrypted) + MIC
Msg 4
Client → AP: Acknowledgement

Key Takeaway: Traditional attacks need all 4 messages (requires connected client). The PMKID attack only needs Message 1 (no client required).

PMK Derivation

PMK = PBKDF2-SHA1(Password, SSID, 4096, 256)
  • ➤ The password itself never travels over the air.
  • ➤ PBKDF2's 4,096 iterations deliberately slow down brute-force attempts.
  • ➤ Both client and AP derive the PMK independently.

The PMKID attack revolutionised Wi-Fi hacking by removing the need for an active, connected client. This section contrasts the traditional methodology with the PMKID approach and details the three-phase toolchain required to execute the attack successfully.

1

Capture

Tool: hcxdumptool

Sends an association request to the target AP to force it to respond with Message 1 containing the PMKID in the RSN IE. The output is a raw .pcapng file.

2

Convert

Tool: hcxpcapngtool

Parses the packet capture to extract the specific PMKID hash. It strips unnecessary network data and outputs a clean text file formatted specifically for Hashcat's unified mode 22000.

3

Crack

Tool: Hashcat (-m 22000)

Utilises GPU acceleration to perform a dictionary or brute-force attack. For each guessed password, it derives a candidate PMK, calculates a candidate PMKID, and compares it to the captured hash. A match reveals the Wi-Fi password.

Defence is the other half of penetration testing. Understanding how an attack works allows us to implement precise countermeasures. This section outlines remediation strategies and visualises the ultimate defence against offline hashing attacks: Password Entropy.

1. Disable 802.11r

Eliminates the primary PMKID exposure mechanism. Not needed in most SOHO setups.

2. Upgrade to WPA3-SAE

SAE handshake resists offline dictionary attacks and provides forward secrecy.

3. Disable Transition Mode

If WPA3 is enabled, don't allow WPA2 fallback, which re-introduces vulnerabilities.

4. Update Firmware

Modern router firmware often suppresses PMKID in RSN IE responses automatically.
