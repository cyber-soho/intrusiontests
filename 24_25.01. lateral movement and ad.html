Active Directory & Lateral Movement

Welcome to Days 24 & 25 of the Intrusion Testing Course. This module covers the core of enterprise network compromise. Over 90% of Fortune 1000 companies rely on Windows Active Directory (AD). It is the single most valuable target in any enterprise environment.

🎯 Why Active Directory Matters

  • ✔️ Compromising one account rarely stays limited to one account.
  • ✔️ Attackers exploit trust relationships, abuse tickets, and reuse hashes to move laterally.
  • ✔️ The ultimate objective is always Domain Admin or equivalent privileges.

⚠️ Rules of Engagement (RoE)

Primary Attack Vectors

Attackers exploit misconfigurations in the Kerberos protocol and Windows credential caching to extract hashes and forge tickets. Explore the primary lateral movement and privilege escalation techniques below.

AS-REP Roasting

Exploits accounts that have the DONT_REQ_PREAUTH flag enabled. Anyone can request an AS-REP for these accounts, which contains data encrypted with the account's NTLM hash, allowing for offline cracking.

The Attack Chain:

  1. Enumerate accounts with DONT_REQ_PREAUTH via LDAP queries or Impacket (GetNPUsers.py).
  2. Send an unauthenticated AS-REQ for each vulnerable account.
  3. Receive the AS-REP and extract the encrypted portion.
  4. Crack the hash offline using Hashcat (mode 18200) or John the Ripper.

Kerberoasting

Any domain-authenticated user can request a Service Ticket for any Service Principal Name (SPN). Because the ticket is encrypted with the target service account's NTLM hash, weak service account passwords can be extracted and cracked offline.

The Attack Chain:

  1. Authenticate to the domain with any low-privilege account.
  2. Query AD for all SPNs (via setspn or Impacket's GetUserSPNs.py).
  3. Request Service Tickets (TGS-REQ) for interesting SPNs (e.g., highly privileged accounts).
  4. Extract tickets from memory and crack offline (Hashcat mode 13100).

Pass-the-Hash (PTH)

Windows uses NTLM hashes for authentication and caches them in LSASS memory. If an attacker extracts a hash, they don't need to crack it — the hash is the credential and can be passed directly to authenticate to other systems.

The Attack Chain:

  1. Compromise an initial workstation (e.g., via phishing).
  2. Escalate privileges to local administrator.
  3. Run Mimikatz (sekurlsa::logonpasswords) to dump NTLM hashes from LSASS.
  4. Identify a privileged hash (like a help-desk user with local admin on multiple machines).
  5. Use tools like Impacket psexec.py or CrackMapExec to authenticate to other machines using only the hash.

Over-Pass-the-Hash

When networks enforce Kerberos-only authentication, standard PTH (which relies on NTLM) is blocked. Over-PTH bypasses this by using the stolen NTLM hash to request a legitimate Ticket Granting Ticket (TGT) from the KDC.

How it works:

  • Converts an NTLM Hash into a Kerberos TGT.
  • All subsequent authentication on the network uses standard Kerberos traffic, making it much harder for defenders to detect.
  • Requires Mimikatz: sekurlsa::pth /user:admin /domain:corp.local /ntlm:[hash]

Total Compromise: The Full Kill Chain

Active Directory attacks chain together. A single misconfiguration combined with password reuse and missing protections leads to rapid domain compromise. Below, analyze the 4 phases of an attack and the critical defenses required to stop them.

The 4-Phase Attack Lifecycle

Phase 1

Initial Access

Phishing leads to local escalation. Attacker runs Mimikatz.

Phase 2

Credential Harvesting

Kerberoasting is executed. A service account password is cracked offline.

Phase 3

Lateral Movement

Pass-the-Hash with the service account hash to the finance server. CFO's hash is dumped from LSASS.

Phase 4

Domain Compromise

Over-PTH with CFO hash allows DCSync. KRBTGT hash extracted. Golden Ticket created.

Result: Total domain compromise in ~3.5 hours
