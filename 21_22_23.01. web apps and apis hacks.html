Key Vulnerabilities Deep Dive

SQL Injection

Attacker inserts malicious SQL into user-facing input, application concatenates it, database executes modified query.

' OR '1'='1' --
Impact
  • Full DB dump
  • Auth bypass
  • Data modification
Defence

Never concatenate input. Always use parameterised queries (prepared statements).

Cross-Site Scripting

TypeWhere
ReflectedHTTP request (URL param) - One-shot
StoredSaved on server (DB) - Permanent
DOM-basedClient-side JS manipulates DOM
Impact

Session cookie theft, account takeover, defacement, malware delivery.

Insecure Direct Object Reference

App exposes internal IDs in URLs without checking if the user owns the resource.

bank.example/doc?id=10042 (Yours)
bank.example/doc?id=10043 (Someone else's!)
Defence

Always verify authorisation server-side. Use indirect references (mapping tables).

Authentication Failures

  • Weak/default passwords permitted
  • Missing or broken MFA
  • Session IDs in URLs
  • No rate-limiting on login endpoints
Defence

Enforce strong policies, implement MFA everywhere, use secure random session tokens.

Lesson 3: Input Validation

The root cause of almost all injection vulnerabilities is trusting user input. Fixing input validation drastically reduces the entire attack surface. This section outlines the principles of proper validation and the necessary multi-layered defense approach.

3-Layer Defence Model

1

Client (Browser)

Usability feedback. Trivially bypassed.

2

Server (Backend)

Security enforcement. Validation happens here.

3

Output (Render)

Context-specific encoding (HTML, SQL, URL).

Validation Strategies Matrix

✔ Allow-list

Define exactly what IS permitted. Reject everything else.

"Only digits 0-9, length 5"
Preferred & Robust
✖ Deny-list

Define what IS NOT permitted. Accept everything else.

"Block inputs containing <script>"
Fragile & Bypassable

Lesson 4: SSRF Overview

Server-Side Request Forgery (SSRF) occurs when an attacker tricks a server into making HTTP requests to unintended destinations. The server effectively মজbecomes an unwitting proxy, often used to access internal networks or cloud metadata APIs.

The Attack Pattern Interactive Flow

1. App accepts URL param
2. Attacker alters URL to internal IP
3. Server fetches internal resource
4. Server returns data to attacker

Key Defences

  • Allow-list outbound destinations
  • Block private IP ranges (127.0.0.0/8, 10.x.x.x, etc.)
  • Enable IMDSv2 in Cloud environments
