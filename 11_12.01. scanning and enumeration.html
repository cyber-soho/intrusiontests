Lesson 1

TCP & UDP Scans

This module explores the core mechanics of network port scanning. You will interact with a visual comparison of different Nmap scan types, balancing speed against stealth, and review the critical differences between TCP and UDP protocols.

TCP (Transmission Control)

  • ✔️ Connection-oriented (3-way handshake)
  • ✔️ SYN → SYN-ACK → ACK
  • ✔️ Reliable, ordered delivery
  • ✔️ Layer 4, OSI Model
Scan Flags: -sS (Stealth), -sT (Connect)

UDP (User Datagram)

  • 🚀 Connectionless (Fire and forget)
  • 🚀 No handshake, no acknowledgment
  • 🚀 Faster but unreliable delivery
  • 🚀 Targets: DNS (53), SNMP (161), DHCP
Scan Flags: -sU (UDP Scan)

Nmap Scan Type Analysis

Compare the operational profiles of common scan flags based on speed efficiency and stealth (likelihood of bypassing basic logging).

💡

Key Takeaway

Never ignore UDP. TCP scans find most services, but critical infrastructure runs on UDP. Combine -sS and -sU for complete coverage. A full UDP scan takes 18+ hours; always scan the top 100 ports first.

Service & Version Detection

Finding open doors is not enough; we must identify what lies behind them. This section breaks down how Nmap's -sV flag operates under the hood and demonstrates why version detection is critical for transforming raw data into actionable vulnerabilities.

The Impact of Version Detection

Without -sV
Port 80 / tcp open

"Something speaks HTTP." Passes standard compliance audits. Generic finding.

VS
With -sV (Actionable)
Apache 2.2.15 on CentOS

Reveals end-of-life software with 30+ known CVEs including RCE. Immediate critical remediation required.

  • 2. Probe Selection

  • 6. NSE Enhancement

Lesson 3

Protocol Enumeration

Enumeration turns open ports into attack paths. Use the tabs below to explore what information can be extracted from SMB, LDAP, and SNMP services, the tools used to extract it, and the severity of common misconfigurations.

📁

Server Message Block (SMB)

Critical Risk: SMBv1 Enabled / Null Sessions

What It Reveals

  • • Share names & permissions (C$, ADMIN$)
  • • User accounts & groups
  • • OS version & build number
  • • Password policy (lockout, complexity)
  • • Active sessions & logged-on users

Key Tools

  • enum4linux -a
  • smbclient -L //<ip> -N
  • smbmap -H <ip>
  • nmap --script smb-enum-*
s📇

Lightweight Directory Access Protocol

Critical Risk: Anonymous Bind Allowed

What It Reveals

  • • All user objects (sAMAccountName)
  • • Group memberships (Domain Admins!)
  • • Organizational Units (structure)
  • • Group Policy Objects (GPOs)
  • • Service Principal Names (Kerberoasting)

Key Tools

ldapsearch -x -H ldap://<ip> -b "dc=lab,dc=local" "(objectclass=user)"

If anonymous bind is allowed, this dumps the entire directory with zero credentials.

🕸️

Simple Network Management Protocol

High Risk: Default "public" Community String

What It Reveals

  • • System description & uptime
  • • Network interfaces & IP addresses
  • • ARP tables (neighbor discovery)
  • • Routing tables
  • • Running processes & installed software

Key Tools

  • snmpwalk -c public -v2c <ip>
  • snmp-check -t <ip> -c public
  • onesixtyone -c wordlist.txt <ip>

Scan Hygiene & Operations

Discipline separates professionals from amateurs. This section covers operational security, footprint minimization, and pre-engagement procedures to prevent network crashes, user lockouts, and scope violations. Use the interactive pre-flight checklist before initiating any scan.

⏱️ Timing Templates

Nmap uses timing templates to dictate scanning aggressiveness. Higher numbers equal faster speeds but higher risks of crashing systems or detection.

-T0 Paranoid IDS Evasion
-T1 Sneaky Slow Evasion
-T2 Polite Production Safe
-T3 Normal Standard
-T4 Aggressive Labs Only
-T5 Insane Never in Prod
