Lesson 1: IDS/Firewall Evasion & Tunneling

Getting past the gatekeepers

About This Section

This module explores how attackers bypass network security perimeters. You will interact with different evasion techniques to understand how the discrepancy between an Intrusion Detection System (IDS) and a target host can be exploited. This section aims to demonstrate that perimeters are not infallible.

🧱

The Firewall "Bouncer"

Monitors incoming/outgoing traffic and decides to ALLOW or BLOCK based on predefined rules.

  • Packet-Filtering: Headers only
  • Stateful: Tracks connections
  • NGFW: Deep packet inspection
👁️

IDS Deployment

Monitors for suspicious activity without actively blocking it (unlike IPS).

  • NIDS: Monitors entire subnet (Snort, Suricata)
  • HIDS: Monitors single host (OSSEC)

💡 The Key Insight

The IDS and the target host process packets differently. Attackers exploit that operational gap.

Lesson 2: Service Misdirection

Making services appear to be something they are not

About This Section

This section covers the concepts of manipulating service identities and routing. You will learn the difference between offensive banner grabbing and defensive banner spoofing, and explore how honeypots are used to study attackers. The goal is to emphasize that port numbers and service banners cannot always be trusted.

🔄 Port Redirection

Forwards traffic from one port or machine to another. This is the cornerstone of pivoting through compromised hosts.

Scenario:

  1. Compromise DMZ web server.
  2. Web server can reach internal DB (3306).
  3. Your machine cannot reach DB directly.
  4. Tunnel port 3306 through the compromised server.

⚔️ Banner Grabbing (Attacker)

Identifying software versions from connection strings to search for vulnerabilities.
Ex: SSH-2.0-OpenSSH_8.9

🛡️ Banner Spoofing (Defender)

Changing the banner to mislead attackers, forcing them to waste time on wrong exploits.
Ex: Apache appears as Nginx

The Deception Strategy: Honeypots

🍯

Honeypot

Decoy system to attract attackers. Captures intel. 100% of traffic is suspicious.
Tools: Cowrie, Artillery

🕸️

Honeynet

Entire network of interconnected honeypots. Allows for longer attacker engagement and better intelligence.

🐌

Tarpit

Accepts connections but responds extremely slowly. Traps and breaks automated scanning tools.

Lesson 3: DoS Concepts & Ethics

The attack that does not steal — it destroys availability

About This Section

This module breaks down the mechanics of Denial of Service (DoS) attacks, contrasting simple volumetric attacks with massive amplification techniques. Because DoS inherently threatens availability, this section strongly emphasizes the legal and ethical boundaries that must be maintained during penetration testing.

Attack Categories

1. Volumetric Attacks

Floods network bandwidth (e.g., UDP/ICMP floods). Like pouring water until the hose bursts.

2. Protocol Attacks

Exploits protocol weaknesses (e.g., SYN Flood). Like starting phone calls but never answering.

3. Application-Layer Attacks

Targets specific apps (Layer 7 HTTP floods). Like 1000 customers ordering the most complex dish at once.

Amplification Factors (Log Scale)

By spoofing the victim's IP, attackers use external servers to multiply their traffic.

⚖️ Penetration Testing Ethics

Never perform DoS testing without explicit, written, scoped authorization. Unauthorized DoS is criminal everywhere (e.g., US CFAA, UK Computer Misuse Act).

1. Explicit Auth: Must be in Rules of Engagement.
2. Scoped: Strict bandwidth limits & time windows.
3. Notification: ISP & internal IT informed.
4. Non-Production: Use staging environments.

Lesson 4: Log / Alert Triage

Sorting the real threats from the noise

About This Section

This final section shifts focus to the defender's perspective inside a Security Operations Center (SOC). It illustrates how raw logs are transformed into actionable alerts via a SIEM, and walks you through the critical triage process required to combat alert fatigue and identify real breaches.

The SIEM Funnel

Millions of raw log lines go in → a prioritized list of potential incidents comes out.

Verdict Matrix

The goal of triage is accurately categorizing the alert.

True Positive Real attack correctly flagged
False Positive Benign event matched rule. Needs tuning.
False Negative Real attack missed. Highly dangerous.
True Negative Correctly ignored normal traffic

The Triage Process Explorer

Step 1 — Initial Assessment

Review alert source, severity, and detection logic. Calibrate signal quality before deep investigation to save time on known noisy rules.

⚠️ The Threat: Alert Fatigue

Thousands of alerts per day, mostly false positives, cause analysts to dismiss alerts without proper investigation. Solutions include: Continuous rule tuning, SOAR (Automation), and UEBA (Behaviour Analytics).
